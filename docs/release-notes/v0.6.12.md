# Agent Workbench v0.6.12

## Highlights

- Linux startup can recover a new abandoned reclaim guard when exact file
  identity, matching kernel scope and positive owner death establish safe deletion.
- Refresh diagnostics count actual executor calls and exclude cancelled pre-run
  attempts.

## Added

- A packaged recovery helper serializes exact dead-guard deletion with a private
  SQLite mutex in a separate process, preserving the native-free MCP bridge.

## Changed

- Startup and shutdown retain their existing deadlines across asynchronous
  recovery. A helper result never grants startup ownership; normal election
  establishes the owner and preserves a successor published during recovery.
- Preserve private `.reclaim.sqlite` authority storage while processes may be
  active. The filesystem must provide reliable SQLite/POSIX locking.

## Fixed

- Proven-dead, scope-qualified Linux reclaim guards no longer permanently block
  subsequent startup. Live, replaced, legacy or uncertain guards remain protected.
- Explicit foreign or unavailable process scope on canonical startup claims
  cannot authorize stale deletion.
- `worker_invocations` increments immediately before `executor.run`, including
  synchronous throws, with diagnostic revision updates.
- Release checksum verification accepts platform line endings while checking
  the exact asset filename and digest.
- Installed smoke establishes the first client's fresh baseline before spawning
  the second client, removing a startup-owner scheduling race in the harness.

## Documentation

- Runtime operations, contracts, threat model and install guidance describe the
  recovery boundary and retained authority storage. Spec 071 records delivery;
  B010/B011 track platform proof and additional cancellation evidence.

## Validation

- Source regression: 150 test files passed, 1,575 tests passed and one
  installed-only case skipped.
- Actual isolated installed entrypoint: all 25 tests passed, including recovery
  through the compiled helper and same-version build handoff.
- Ordinary isolated npm/native smoke passed, including six grammar routes,
  SQLite, shared-daemon refresh convergence and cleanup.
- Typecheck, runtime build receipt, contracts, plugin and package checks passed.
  Independent correctness and security reviews found no blocking issues.

## Known issues

- Automatic dead-guard recovery requires verifiable Linux boot/PID namespace
  scope. Legacy and unprovable guards remain blocked; non-Linux proof is B010.
- A real paused-helper cancellation fixture remains additional test hardening
  under B011. Existing cancellation fences and tests passed review.
- Broader legacy canonical-owner and endpoint migration policy remains Spec 065;
  this release does not establish complete cross-PID-namespace daemon ownership.
- Restart existing agent sessions after installing the new package and refreshing
  the plugin so they load the new runtime.
