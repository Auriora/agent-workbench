# Agent Workbench v0.6.7

## Highlights

- Completes the rolling-upgrade fix by allowing a newly installed runtime to
  initialize while retained sessions still use an older repository daemon.
- Keeps graph refresh single-owner without making refresh ownership a
  prerequisite for serving MCP requests.

## Fixed

- Fixed v0.6.6 daemons exiting with `Repository refresh owner is active` when
  an older runtime retained the repo-wide refresh lease.
- A new runtime identity can now start as a ready observer, serve the compatible
  published graph, and report blocked refresh admission until the lease becomes
  available.
- Preserved synchronous orphan reconciliation and controller diagnostics when
  refresh ownership is immediately available.
- Tightened direct same-identity startup exclusion so only the exact PID and
  launch token may continue a `starting` attempt; competing attempts cannot
  unlink the healthy endpoint.

## Changed

- Daemon bootstrap now uses the existing lazy ownership-gated refresh authority
  as its only refresh control path.
- The lazy authority can prepare ownership and recovery during bootstrap while
  retaining structured `owner_active` behavior for observers.

## Validation

- TypeScript typecheck passed.
- The complete serial Vitest run passed 1,114 tests across 103 files.
- All 52 daemon-launch tests and all 18 real daemon-entrypoint integration tests
  passed.
- Plugin validation, package dry-run, owned-skill validation, and patch checks
  passed.
- A compiled checkout initialized, listed tools, and returned daemon health
  beside a live v0.6.4 daemon that retained refresh ownership.
- Independent architecture re-review found no remaining blocker.

## Upgrade Note

- Users on v0.6.6 should install v0.6.7 and refresh the provider plugin before
  starting a new session. Existing older sessions may remain alive; v0.6.7 does
  not kill or adopt their daemon.
