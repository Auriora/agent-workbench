# Agent Workbench v0.6.6

## Highlights

- Fixes MCP startup failures after an Agent Workbench upgrade when retained
  sessions are still using an older repository daemon.
- Preserves valid older sessions during rolling upgrades instead of killing,
  adopting, or overwriting their daemon state.

## Changed

- Daemon lifecycle receipts and startup locks now use the same short daemon
  identity hash as the local IPC endpoint.
- Different runtime, graph-schema, protocol, or repository identities now have
  independent admission state, while concurrent clients with the same identity
  still converge on one daemon.
- Rolling upgrades may temporarily retain one daemon per active runtime
  identity for a repository. Repository graph refresh remains serialized by
  the existing ownership lease.
- Release metadata integration checks now derive the expected release version
  from the package rather than pinning the previous version.

## Fixed

- Fixed Codex reporting `connection closed: initialize response` when a newly
  installed runtime encountered a live legacy `daemon.json` or `startup.lock`.
- Fixed shared unsuffixed admission files causing
  `blocked: ambiguous_process` across runtime versions.
- Legacy unsuffixed admission files are now ignored without deleting them or
  signalling their possible owner.

## Documentation

- Extended Spec 046 with rolling-upgrade requirements, design, traceability,
  verification, and review evidence.
- Updated the runtime contracts, operations design, installation guidance, and
  Codex runbook with identity-scoped admission and released-version diagnosis.

## Validation

- TypeScript typecheck passed.
- The complete serial Vitest run passed 1,111 tests across 103 files before the
  version bump; the release-metadata integration suite passed again against
  the v0.6.6 package metadata.
- Plugin validation and package dry-run passed.
- The installed-tarball smoke seeded positively live legacy admission files,
  initialized two concurrent compiled MCP sessions, exercised tool and resource
  calls, verified both sessions shared one current daemon, preserved the legacy
  files byte-for-byte, and completed bridge, daemon, socket, metadata, and
  temporary-root cleanup.
- Independent architecture, specification/QA, operations, and documentation
  review completed with all findings reconciled.

## Known Issues

- Legacy admission files may remain in ignored repository cache state until the
  older runtime shuts down or an operator performs cache maintenance while no
  Agent Workbench runtime is active. They do not block v0.6.6 admission.
- Bridge count remains determined by provider-owned MCP connections and agent
  concurrency; v0.6.6 does not pool independent stdio streams.
