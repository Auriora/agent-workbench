# Agent Workbench v0.6.13

## Highlights

- Repository refresh on the fixed 336-file synthetic workload now uses 49.3%
  less median process CPU and 41.0% less wall time, with graph equivalence after
  the independently expected Qt, schema and accounting corrections. This characterises the synthetic workload only; it is not a
  claim about every repository or FreeCAD-scale workloads.
- Startup verifies the guarded native build before loading it. Terminating a
  long native parse preserves the host and ordinary callback error behavior.

## Added

- Bounded Qt translation admission and signature checks avoid sending positive
  Qt files through the TypeScript parser.
- Reusable inventories, compiled path matchers, reference candidate indexes,
  and explicit refresh phase budgets reduce repeated work while preserving
  graph results.
- Graph-v4 owned empty-store rebuild and rollback procedures now require
  stopped owners and make ownership and rollback state explicit.

## Changed

- The canonical native source build is guarded by a build receipt and requires
  Python plus a C/C++ toolchain (C++20) on every Node installation. The build
  uses the pinned tree-sitter and node-gyp versions and the supported native
  termination-safe build policy.
- Refresh accounting reports bounded phases and does not publish partial
  timeout output. Package and install documentation now describe the native
  prerequisites and guard checks.

## Fixed

- Native overrun termination no longer aborts the host process.
- Positive Qt signatures are admitted without TypeScript parser calls.
- Repeated catalog, ignore-policy, inventory, and reference-candidate work is
  avoided within a refresh.
- Distinct progress counters no longer accumulate overlapping scan windows;
  legacy totals remain unknown until an explicit rebuild.
- Interrupted profiling now writes freshness through the reopened store handle.

## Documentation

- Runtime architecture, graph-store, operations, observability, contracts,
  native dependency, install, and plugin runbooks were updated.
- The daemon CPU efficiency audit and its machine-readable evidence are
  retained in the history record, including the benchmark scope and follow-up
  backlog.

## Validation

- Full source validation: 182 test files, 1,816 tests passed, one skipped;
  typecheck, runtime build receipt, plugin validation, and focused native
  guard/build/termination checks passed.
- An isolated Linux installed-package smoke run passed on Node 24.8.0, including
  native parse termination, guard rejection before native load, callback error
  identity, and cleanup. This is historical installed-package evidence, not a
  live-upgrade result.
- The fixed synthetic benchmark measured 49.3% lower median process CPU and
  41.0% lower median wall time across five complete repetitions per scenario.

## Known Issues

- Publication is gated on the actual Windows2022/Node22 portable preflight in
  this release workflow. Older Windows runs cannot substitute for that proof.
- The largest end-sampled idle RSS observation rose 13.7%; the bounded audit
  accepts this tradeoff with memory characterization follow-up B016. Exact
  allocation causes remain unknown. Background indexing duty-cycle policy (B014) and
  moderate native build dependency advisories (B015) remain backlog work.
- Installing the package does not replace a running daemon. Follow the
  documented stopped-owner upgrade procedure before starting the new runtime.
