# Agent Workbench v0.6.3

## Highlights

- Reduces the per-connection cost of retained MCP stdio bridges by moving
  distributed launches from TypeScript runtime loading to compiled ESM.
- Keeps repository services in one shared daemon while making bridge lifetime
  follow the client-owned stdio transport instead of task-completion guesses.
- Hardens daemon startup and refresh admission so concurrent clients share one
  bounded startup path and do not receive readiness before the repository
  runtime is ready.

## Added

- Added a deterministic runtime build command and receipt covering runtime
  sources, `package.json`, `tsconfig.json`, esbuild version, build options,
  entrypoints, and generated outputs.
- Added compiled stdio, daemon, and graph-warmup worker artifacts to npm,
  plugin, container, and installed-package validation.
- Added negative tests for stale or missing build output, native bootstrap
  failure, bounded npm-bin errors, and repository-local build failure before
  plugin registration.

## Changed

- Codex, Claude Code, Kiro, npm-bin, package-script, container, and
  repository-local launch surfaces now converge on
  `dist/mcp/stdio-entrypoint.mjs`.
- The stdio bridge now imports only lightweight daemon-client contracts;
  repository graph, parser, SQLite, and server ownership remain in the shared
  daemon.
- Repository-local Codex installation builds and validates the candidate before
  refreshing marketplace and plugin registration.
- Agent Workbench guidance now activates around unverified repository claims
  and explicit trust boundaries rather than a broad trivial/non-trivial task
  distinction.

## Fixed

- Fixed retained bridge processes loading the full TypeScript/server dependency
  graph for every open client or subagent connection.
- Fixed daemon startup races that could expose a socket before bounded metadata
  admission and readiness completed.
- Fixed package creation accepting generated runtime output without an
  independent post-build receipt comparison.
- Fixed runtime-build cleanup deleting unrelated output under `dist/`.
- Fixed Windows Node 24 rebuild guidance to use `_CL_=/std:c++20`.

## Packaging And Installation

- Package, server card, Codex plugin, Claude Code plugin, MCP bindings, and
  distribution manifests are synchronized at `0.6.3`.
- `tsx` remains a developer dependency for source execution but is not required
  by the compiled distributed bridge.
- Existing provider sessions keep the bridge and daemon with which they
  started. Restart the coding-agent session after upgrading.

## Documentation

- Added Specs 045 and 046 with traceable requirements, design, implementation,
  review, resource evidence, and closure-readiness records.
- Promoted compiled-runtime ownership, provider-owned bridge cardinality,
  installation recovery, and rollback guidance into the canonical runtime,
  integration, and Codex runbook documents.

## Validation

- The release candidate passed TypeScript typecheck and 1,109 Vitest tests
  across 103 files in the complete serial regression run.
- Plugin validation, skill validation, developer CLI tests, package dry-run,
  installed-tarball cold-refresh smoke, repository-local installation, and
  source-launch smoke are release gates.
- A controlled same-host observation measured the compiled bridge at 56,092
  KiB RSS versus 94,412 KiB for the source `tsx` bridge. This is host-specific
  evidence, not a portable resource guarantee.

## Known Issues

- Bridge count remains determined by the provider's open MCP connections and
  configured subagent concurrency. Agent Workbench cannot pool independent
  stdio streams without provider-supported multiplexed transport.
- A healthy per-repository daemon survives client reloads by design; upgrading
  the bridge does not forcibly terminate that shared daemon.
- The repository-local installer is POSIX-only. Windows users should install
  the packaged release.
