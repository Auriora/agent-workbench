# Agent Workbench v0.6.8

## Highlights

- Adds parser-backed Ruby and bounded Rails navigation so agents can find
  modules, classes, methods, constants, routes, controllers, models, concerns,
  and conservative static relationships through the existing Workbench tools.
- Adds repository-composition awareness for nested project units and Git
  submodules, with per-unit provenance and validation evidence instead of
  treating a mixed repository as one undifferentiated workspace.
- Adds a changed-files context entry point, scalable Markdown auditing, and
  public-contract drift checks for more focused reviews and safer releases.
- Improves snapshot recovery, daemon replacement, documentation routing, and
  public error redaction for more reliable long-running agent sessions.

## Added

- Ruby uses the approved `tree-sitter-ruby` parser path and publishes bounded
  partial-semantic evidence through symbol, reference, impact, and task-context
  routes. Dynamic or ambiguous Ruby and Rails behavior remains unresolved
  evidence rather than being guessed through a fallback parser.
- Rails project-shape, route, association, concern, and validation-guidance
  signals now support standard, engine, and non-standard fixture layouts.
- Repository composition discovers nested project units, declared submodules,
  and their source Git claims while keeping evidence scoped to the owning unit.
- `changed_files_context` connects a Git change set to relevant symbols,
  references, documentation, validation guidance, and bounded risk evidence.
- Contract-drift validation compares public runtime documentation and the MCP
  server card with canonical schemas. CI and release publication now enforce
  that check.

## Changed

- `repo:///docs/map` and its continuation tool return bounded, deterministic
  pages; large Markdown audits use stable cursor-based chunks rather than
  returning oversized results.
- Validation planning gives precedence to safe commands from governing
  repository guidance, including Docker-first Rails and repository-wrapped
  validation paths.
- Documentation inventory excludes embedded fixture documentation from the
  containing product while retaining it when the fixture is the selected root.
- GHCR images are now published only after the main release workflow completes
  metadata, tests, plugin, skill, package, and release-artifact validation.
- The Windows Node 24 native rebuild helper now appends `/std:c++20` through
  MSVC's `_CL_` override while preserving existing compiler environment flags.

## Fixed

- First-read snapshot checks now detect files changed while no watcher was
  active and request a coordinated refresh before indexed evidence is reused.
- Stale snapshot recovery and same-version daemon replacement now converge on
  the current installed runtime without adopting or masking incompatible state.
- MCP failure details are consistently bounded and redacted across public tool,
  resource, and debug surfaces.
- Installed-package smoke tests and startup visibility are deterministic across
  daemon warmup and launcher convergence.

## Documentation

- Updated runtime contracts, architecture, language capability, workspace
  safety, installation, provider integration, and lifecycle records for the
  capabilities above.
- Closed and archived the implementation packages completed since v0.6.7;
  remaining work stays routed through the canonical backlog.

## Validation

- TypeScript typecheck, public-contract drift validation, plugin/package
  metadata validation, owned-skill validation, and package dry-run passed.
- The complete Vitest suite and the focused cross-platform native-rebuild tests
  passed.
- The release preflight, installer dry-run, packaged MCP integration tests, and
  the `v0.6.8` release-trigger dry-run passed without publishing or tagging.
- A locally installed v0.6.8 Codex plugin started the current daemon, exposed
  all registered MCP surfaces, and completed bounded pagination calls.
- Validation included platform-independent coverage for the Windows rebuild
  contract; a live Windows/MSVC rebuild was not run in the Linux checkout.

## Upgrade Note

- Install v0.6.8, refresh the provider plugin, and start a new session. Source
  installs whose Node ABI changed should run `pnpm rebuild:native`; Windows
  Node 24 rebuilds use `_CL_=/std:c++20`.

## Known Issues

- Ruby and Rails evidence is bounded static navigation, not proof of runtime
  dispatch, a booted route set, callback execution, or association validity.
