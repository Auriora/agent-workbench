# Agent Workbench v0.6.10

## Highlights

- MCP client failures are isolated, daemon lifetime evidence survives restarts,
  and shutdown settles refresh and application work before releasing ownership.
- Finite session, input, request and output budgets preserve an established
  healthy client's small requests during another client's saturation.
- A Windows x64 portable ZIP bundles Node 22 and native dependencies.
- Ordinary npm installation resolves the Ruby and TypeScript dependency
  contracts without peer-bypass flags.

## Added

- A governed Windows portable build, configuration and verification path with
  payload hashes, source/deployment lock identities and release attestations.
- Privacy-bounded aggregate product analytics in official release packages.
  Set `AGENT_WORKBENCH_ANALYTICS_ENABLED=false` before starting the host to opt
  out. Events exclude repository content, paths and user identity. Optional
  PostHog operational logs remain disabled by default.
- Private bounded lifetime receipts distinguish observed daemon outcomes from
  unknown prior-owner loss without retaining raw stderr or client payloads.

## Changed

- Shutdown uses one finite drain budget and blocks successor startup when
  refresh termination or application work remains unsettled.
- Incomplete-frame inactivity and aggregate admission have explicit limits and
  terminal accounting. Cancellation does not free running work prematurely.
- Native grammar dependencies use sealed, metadata-corrected upstream payloads
  pinned to immutable project commit URLs. Parser sources, bindings, prebuilds
  and licenses are unchanged; provenance checks constrain every allowed delta.

## Fixed

- Bridge stdout/stderr failures and backpressured sends no longer destabilize
  unrelated daemon clients.
- Duplicate request IDs, excess admission and serialization failures settle
  through explicit terminal paths without truncated successful output.
- Ruby and TypeScript peer ranges, including TypeScript's JavaScript dependency,
  agree with the supported Tree-sitter 0.25 runtime family.
- Release version bumps include the canonical Codex install runbook. Release
  notes can write draft, evidence and instruction files outside the checkout.
- Packaged runtime startup supports Windows drive paths and installation folders
  containing URL-sensitive characters.
- Windows package staging, deployment links, hook quoting and configuration-root
  handling are validated by the portable workflow.

## Documentation

- Runtime contracts, threat model, operations and install guidance describe
  admission, safe draining, native dependency provenance and recovery limits.

## Validation

- Full source regression covers over 1,500 tests, including transport, shutdown,
  admission, packaging and URL-sensitive launch fixtures.
- Installed entrypoint suite: 24 tests passed, including the conditional build
  handoff case and admission saturation while a healthy client remains callable.
- Ordinary isolated npm install, clean npm dependency validation, six native
  parser fixtures, SQLite and shared-daemon convergence passed.
- Typecheck, contracts, plugin and owned skills, dev CLI, package payload,
  runtime receipt, hook and compiled-launch checks passed.
- Cross-platform native fixtures include Linux ARM64; publication follows the
  governed platform and Windows portable release gates.

## Known issues

- A process dying during startup reclamation can leave a private `.reclaim`
  guard that keeps later startup blocked. Automatic abandoned-guard recovery
  remains B008 under Spec 065; preserve ambiguous ownership evidence.
- Admission accounts retained wire bytes and queued work, not total process
  heap/RSS or malformed-input CPU-rate limits.
- Refresh invocation diagnostics can count a cancelled pre-run attempt (B009).
  Execution and termination receipts remain the safety evidence.
